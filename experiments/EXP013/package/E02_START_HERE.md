## Recovery

- **Ordinary browser disconnect:** the server process may continue. Reconnect and inspect its output. Do not start another worker merely because the browser disconnected. Browser availability does not guarantee VM survival.
- **Python kernel restart:** the owned worker receives a parent-death signal. Run sections 1 onward. A valid local checkpoint is reused, with exact source/runtime checks; if local state disappeared, the latest verified Drive generation is restored. The science runs in fresh pinned child processes, so installing pins does not require an extra kernel restart solely because frontend packages were already imported.
- **Complete VM reset:** reopen the same notebook, reconnect Drive and Run all. The bundle is retrieved from Drive, dependencies are checked, and the latest complete, hash-verified generation is restored into empty local storage. The bundle should not need re-uploading. Drive authorisation may be requested again.
- **Different GPU/software:** restoration stops without editing identities or deleting backup state. The confirmed old device had 85,094,825,984 bytes; the new 40GB device has 42,405,855,232 bytes. They are different runtime identities. A future change within E02 is also a change, even between two nominally similar Colab runtimes. Preserve the prior directory. A deliberately new environment can use a different `RUN_SLOT`, but this starts a separate run and must never be described as an exact resume. No automatic cross-GPU migration or refitting occurs.

## Bounds and troubleshooting

- Compute-operation deadline: **180 seconds**. First complete FIT+STOP epoch: **1,200 seconds**, including its safe-boundary work. Complete smoke invocation: **1,800 seconds**. Individual remaining full-batch probe: **600 seconds**. These are abort-and-diagnose bounds, not claimed runtimes or reduced epochs. An interrupted full epoch resumes from its last verified state.
- Training backup becomes due every **600 seconds** and is taken at the next completed FIT/STOP batch; fit completion and each scientific stage force a backup. Checkpoints include optimizer/RNG/sampling/validation state and CATCH mask gradients/schedulers. The last two complete generations are retained. Unchanged `.pt` files are not recopied. A failed copy stops execution and preserves the previous verified generation. Transfer time, a slow batch and long scoring calls mean there is **no hard 15-minute wall-clock loss guarantee**. Score caching commits whole calls; a long uncommitted call must repeat.
- On a timeout, inspect `operation.json`, `progress.jsonl` and `worker_stdout.log`. Failure diagnostics are copied to Drive after worker shutdown. Do not rerun a known failing operation indefinitely. SIGKILL alone does not identify the cause. The original 45-minute failure has not been attributed conclusively.
- On CUDA OOM or less than 5% observed memory margin, stop. Do not reduce batch size, dimensions, precision or sequence length. The preserved settings may require a larger device. The actual full-batch checks, including Adam allocation and checkpoint restoration, determine feasibility. A dense parameter-state estimate does not prove peak fit. No automatic GPU upgrade, baseline exclusion or substitution is made.
- On Drive quota/authentication/copy failure, repair connectivity or storage and rerun. Keep about **20 GiB free locally and 20 GiB in Drive**; CATCH MSL checkpoints are large. This is a practical recommendation, not a measured maximum. Stale partial files can consume space but never count as recovery states. Preserve them for inspection if the first-ever backup did not complete.
- A checksum/source/freeze failure is an integrity stop. Preserve the files; do not edit manifests, gate flags or RUN_FREEZE to get past it.
